## 2026-11-19

- Added the opt-in, closed `catalog.entries` contract for public website and app
  listings. Validation bounds public fields, permits explicit retirement,
  requires exact public static routes, rejects redirect sources/private route
  shadows, and keeps images on the authorized draft or approved public asset host.
  Create/upsert rejects invalid input before storage and publish revalidates the
  exact immutable stored package. Legacy packages are unchanged.
- Added optional `catalogRevision` to the existing published pointer. Its
  schema version, next registry revision, canonical entries SHA-256, and count
  are committed atomically with the pointer using the existing conditional
  write. Empty entries retain withdrawal evidence; absent catalog retains the
  legacy pointer. TEST publication preserves production. No entry projection,
  endpoint, extra table/storage write, IAM change, or deployment was included.
- Added contract-first coverage for offline validation, generic errors,
  pre-storage rejection, stored-package revalidation, digest canonicalization,
  rollback to an exact stored version, withdrawal, legacy equality, revision
  conflicts, and environment isolation.
- Added an unconnected internal projection primitive with strongly consistent
  source resolution, stored snapshot verification, approved source/entry binding,
  and whole-document monotonic conditional writes in the existing table. Replay
  is idempotent; newer documents win; declared withdrawals and legacy fallback
  tombstones are distinct. Tests document the nontransactional publication race
  and its reconciliation boundary. API actions, IAM, workflows, and publish
  behavior remain unchanged; the primitive is not activated or deployed.
